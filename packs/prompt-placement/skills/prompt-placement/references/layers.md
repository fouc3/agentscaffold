# 每一层的详细判据与写作模板

## 根 AGENTS.md（常驻，最贵）

**准入条件**（全部满足才放这里）：

- 对仓库里**每个模块**都成立；
- **每次会话**都必须遵守，不是偶发场景；
- 违反时能**一眼判定**（不依赖主观审美）。

**行数预算**：100 行以内。超了不是「再压一压」，而是「有东西该下沉」——
回头做一次搬迁审计。

**结构模板**：

```markdown
# Global instructions

<3–8 条硬规则，每条一段：祈使句 + 例外的边界>

<如果这些目录有更细的约定，就在根文件里列出目录名>
When working under any of the following directories, read the AGENTS.md there first:
 - `js/`
 - `gfx/wr/`

## Tooling
<有哪些工具、什么时候用；不要复述这些工具自己会输出的帮助>

## Workflow
<提交/评审/分支这类跨模块流程；细节指向技能>
```

**写法对照**：

| 不好 | 好 |
| --- | --- |
| 注释要适当 | 几乎不要加注释，除非非显然的代码、参数不自解释的函数、类定义 |
| 注意性能 | 热路径里禁止每次循环分配；需要分配时提到循环外 |
| 遵循项目规范 | 缩进 2 空格；文件名用 kebab-case；测试与被测文件同名 |
| 建议先写测试 | （这类"建议"要么升级成硬规则，要么删掉） |

## 子目录 AGENTS.md（按需）

**准入条件**：只在该目录/该技术栈成立的事实或约定。

**内容清单**（按需取用，不必都写）：

- 构建与测试命令（含只在本目录生效的参数）
- 命名与文件组织约定
- 本目录特有的坑（"这个目录下的 X 会由 Y 生成，不要手改"）
- 与其他模块的边界（"改动这里必须同步改 Z"）

**不要**：

- 复述根文件的全局规则（重复 = 两处可能不一致）
- 写成长教程；超过一百多行就该考虑拆成技能 + references

## 技能（`skills/`，描述常驻、正文按需）

**准入条件**：是「做一件事的流程」，而不是「一段知识」。

**`description` 模板**（这行是常驻成本，必须精确）：

```yaml
description: >
  <做这件事的一句话定义>。
  当用户 <触发场景 1>、<触发场景 2>、<触发场景 3> 时使用。
  不负责：<最容易误触发的相邻领域 1>、<相邻领域 2>。
```

三条要求：

1. 用**用户会说的话**写触发场景（"某测试变慢了" 而不是 "performance regression triage"）。
2. **必须写"不负责"**：相邻领域不划清，误触发会常态化。
3. 不写实现细节；细节写进正文，正文再按需指向 `references/`。

**正文模板**：

```markdown
# <技能名>

## 什么时候用 / 不用   ← 与 description 呼应，可写更细
## 步骤                ← 有序、每步有产出；说明哪些步骤不能跳
## 硬约束              ← 不许做什么（例如"未经批准不许 push"）
## 常见错法            ← 反模式清单
## 参考                ← 指向 references/，并写明走到第几步才读哪一篇
```

## 结构化配置（机械路由）

**准入条件**：这个「什么时候该加载」的判定**能被机器做**（文件路径、扩展名、关键字、目录前缀）。

写法（以 `review-context.toml` 为例）保留了最好的三点，值得照搬：

1. **规则是数据**：`when`（匹配条件）+ `load`（加载什么），一行一条，可被工具执行。
2. **能进 lint**：文件头写明校验命令（`./mach lint review-context.toml`），配置因此被当成代码维护。
3. **描述与文件都写在规则里**：命中的时候你能知道"为什么加载了这个"，便于排查。

如果你没有现成的配置机制，最小可用实现是：在根文件里写一张表
「目录/扩展名 → 该读的文件」，让 agent 在动手前按表加载。虽然仍靠自觉，
但比"靠描述猜测"稳定得多。

## 迁移的安全做法

1. **一次只搬一类**（例如先搬"模块细节"），搬完跑一遍验证再继续。
2. **先加索引，再删内容**：根文件里先写上新位置，确认能找到，再删旧段落。
3. **保留"单一真源"**：内容搬走后，原处最多留一行指针，不要留半份。
4. **有 lint 就进 lint**：能机械检查的部分（路径是否存在、索引是否指向真实文件）交给检查。
