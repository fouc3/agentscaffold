# 提示词该放哪一层

## 一句话原则

提示词的成败不在「写多长」，而在「放哪层」——**常驻的越短越好，按需的越准越好。**

## 成本模型（后面所有判断都由它推出来）

| | 什么时候付成本 | 例子 |
| --- | --- | --- |
| **常驻** | 每次会话都要 | 根 `AGENTS.md` 全文；每个技能/子文件的 `description` |
| **按需** | 只有命中时才付 | 技能正文、技能的 `references/`、子目录 `AGENTS.md` |

推论只有一条：**新内容默认进按需层**。只有「对每个模块都成立」且「每次都必须遵守」的内容，
才配进常驻层。

## 四层的职责

| 层 | 放什么 | 不放什么 | 预算 |
| --- | --- | --- | --- |
| 根 `AGENTS.md` | 跨模块硬规则；全局工具与工作流入口；指向下层的索引 | 单个模块的技术细节、教程、长案例 | **100 行以内**（Firefox 是 73 行） |
| 子目录 `AGENTS.md` | 该目录专属的：构建/测试命令、命名与风格、常见坑 | 全局规则的复述 | 每份几十到一百多行（Firefox 实测 31–128 行） |
| 技能（`skills/`） | 做一件事的流程：何时用、按什么顺序、哪些不许做；长内容进 `references/` | 只在某个目录才成立的事实 | 描述一行以内，正文按需 |
| 结构化配置（如 `review-context.toml`） | 能被机器判定的路由：什么文件 → 加载哪份技能 | 散文式说明、教程 | 越小越好 |

## 放哪层：按顺序问，命中即停

1. **只在某个目录或技术栈成立？** → 子目录 `AGENTS.md`
2. **是「做一件事的流程」（多步、有顺序、有产出）？** → 技能
3. **能被文件路径 / 扩展名 / 关键字机械判定「何时该用」？** → 配置里写一条路由，正文仍放技能
4. **对每个模块都成立，且违反时能一眼判定？** → 根 `AGENTS.md`，而且必须短
5. **其余**（教程、案例、背景、历史） → 技能的 `references/`，或者干脆不写

## 每条规则怎么写

- 硬规则用祈使句 + **可判定的边界**：写「几乎不要加注释，除非参数不自解释」，
  而不是「注释要适当」。
- 一条规则只说一件事。一条里塞三个要求，被违反时你无法定位是哪一条。
- **写清什么时候不适用**，否则会被过度执行到不该动的地方。
- 别在根文件里复述工具自己就能发现的事（构建命令、目录结构）。
- 规则与建议分开：`建议` 只能是建议，别伪装成规则——伪规则会让真正重要的规则贬值。

## 反模式（见到就改）

| 反模式 | 后果 | 改法 |
| --- | --- | --- |
| 根文件变成百科：每加一个模块就往根文件写一段 | 常驻成本线性上涨，真正的硬规则被淹没 | 下沉到该模块的 `AGENTS.md` |
| 把建议写成硬规则（「尽量…」「建议…」） | 规则贬值，agent 学会挑着看 | 要么写成可判定的，要么删 |
| 技能只当文档用：没有步骤、没有产出 | 读完了也不知道要做什么 | 它不该是技能，或改成流程 |
| `description` 写得像「关于 X 的一切」 | 每个会话付成本，却很少命中 | 收窄到「什么时候该用 + 什么时候不该用」 |
| 模块约定只在聊天里说过 | 换会话就丢 | 落到该模块的 `AGENTS.md` |
| 长案例塞在主文件里 | 常驻层被长文本挤占 | 拆到 `references/`，正文写明「第几步才读哪一篇」 |
| 靠模型猜「要不要加载」 | 该加载时没加载，不该时乱加载 | 能机械判定的写进配置路由 |

## 体检一个仓库（可照做的五步）

1. **数**：根文件行数；常驻 `description` 的个数；各子目录 `AGENTS.md` 的份数与行数；技能数。
2. **标**：把根文件每一段标注为「全局硬规则 / 模块细节 / 教程案例 / 索引」。
   模块细节与教程案例就是搬迁候选。
3. **搬**：先搬最贵的——常驻里**最不常用**的内容（通常正是模块细节），
   搬到对应子目录或技能的 `references/`。
4. **留索引**：根文件里保留一行「哪些目录有更细的约定」并列出路径。
   不留索引，下沉之后就没人找得到（Firefox 的做法：在根文件里逐条列出这些目录）。
5. **复查**：搬迁后根文件明显变短，且索引指到的每一份文件都真实存在、内容确实覆盖了搬走的东西。

## 和其他机制配合

- 根文件里**按名字引用技能**，让 agent 知道「这件事有技能」，而不是指望它自己发现。
- 能机械路由的（文件 glob、扩展名、目录前缀）不要只靠描述命中——写进配置文件，让工具决定。
- 大型仓库通用约束（「不要盲目全仓搜索」这类）属于根文件：它对每个模块都成立。
